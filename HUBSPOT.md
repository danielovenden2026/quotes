# HubSpot contact lookup

Open the authenticated `/workspace`, create a draft (or revision), then use **Customer & quotation → Choose HubSpot contact → Connect HubSpot**. Enter the private app token in that form. It validates Contacts read (`crm.objects.contacts.read`) and Companies read (`crm.objects.companies.read`) before saving.

The integration uses the existing exact `COST_ADMIN_USER_IDS` allowlist. Being signed into a public site alone grants no CRM access. Add authorised staff IDs through protected hosting configuration, not client settings. Public demos have no CRM picker or searchable CRM endpoint.

Search by name/email to see each contact’s address plus all linked companies and their vendor numbers, select a contact, check the preview, and click **Use this contact**. Company associations are read in batches with per-contact pagination. Successful rows survive partial/multi-status errors; missing rows retry via paginated individual association reads, three at a time. If company lookups remain unavailable, contact search/selection remains usable with explicit company warnings (never represented as no linked companies); shared companies are loaded once per result page. Empty vendor numbers display as Not provided; unavailable lookups display as Unavailable with a warning. Contact `firstname`, `lastname`, `email`, `address`, `city`, `state`, `zip` map to the quote. Company associations supply names and the custom **Verdex Vendor No** property; company addresses are never imported. The server resolves the property’s internal name using the company properties API and its label (case/spacing/punctuation insensitive), then reads its value only on the selected company. Duplicate labels or unavailable property metadata produce a warning without blocking contact selection. If HubSpot denies property metadata access, enable company property/schema read access on the private app. Multiple linked companies require a choice. Missing address fields stay blank with a warning. Selecting a contact/company fills Vendor Number from that company when available, retaining leading zeros. An empty company value clears the quote vendor number. Changing contacts or companies clears any previous vendor number if lookup is unavailable, along with customer reference and terms. Manual vendor entries are preserved when reselecting the same contact/company only if lookup is unavailable. Quote changes persist when the user saves the draft. Contact and selected company IDs are retained for future integrations, but no CRM records, deals, notes or activities are written by this integration.

## Server configuration

- `HUBSPOT_CREDENTIAL_KEY`: base64-encoded 32-byte random AES-256 key, stored as a server secret. Keep this stable. If rotated, reconnect with the token.
- `BUCKET`: existing private R2 binding. The admin connection form stores only an AES-GCM encrypted token at `integrations/hubspot/credential-v1`, with a random nonce and authenticated context. No public file-serving route exposes this key.
- Optional `HUBSPOT_ACCESS_TOKEN`: hosting-managed secret. When set, it takes precedence and connection changes must be made in hosting settings.

The setup form clears its password input on submission/close. Tokens are never returned to the browser, saved to browser storage, logged, or sent to customer pages. API responses use private/no-store headers; all operations require an allowlisted user and same-origin JSON POST. HubSpot HTTP failures are mapped to fixed safe messages. Disconnect deletes the stored encrypted token; revoke it in HubSpot too if retiring the app. Existing quotes retain their selected customer details.

If either of the two explicitly shared sample quotes is repurposed for a HubSpot contact, its public demo substitutes ABC sample customer details and omits CRM IDs, references, terms and PO/instructions. Customer details remain available in the owner's authenticated quote.

Run `node scripts/test-hubspot.cjs` for mocked integration and security checks, and `npx tsc --noEmit` for types. A real token is required to verify live account data. The connection form performs that live verification without requiring a token in chat or source code.

## Workspace connections

Authorised admins now have three header views: Customer view, Sales workspace and Workspace connections. Opening connections preserves the current quote and unsaved quote edits. Connection settings are separate from quote drafts. The HubSpot card can connect/replace a token, test contact/company access, or disconnect; the contact picker remains available in the quote.

The Google Sheet card accepts an ID or Google Sheets URL plus tab name. It imports SKU/Average Cost and optional Total Stock/Melbourne/Brisbane/Sydney columns. The XML card accepts public HTTPS feeds under `verdex.com.au/media/` or `www.verdex.com.au/media/`. Arbitrary fetch destinations, redirects, URL credentials and query strings are rejected. Saving validates and fetches the candidate first, so an unavailable or malformed source does not replace a working setting. Test does not save. Refresh saved source bypasses the existing cache using the persisted configuration, regardless of unsaved form edits.

Validated source settings persist in private R2 at `integrations/google-sheet/settings-v1` and `integrations/product-feed/settings-v1`. Existing server environment sheet settings and the default Magento feed remain fallbacks until overridden. Settings are read server-side on each lookup, while data is cached for 15 minutes per configuration. Google authentication remains isolated behind `createCostSource` for future provider replacement. Changes do not rewrite saved quote line prices or customer details. `/api/admin/connections` enforces the existing admin allowlist, same-origin JSON writes, bounded request bodies and private/no-store responses. It returns configuration/counts, never raw cost rows or tokens. Public demos cannot manage connections.

Run `node scripts/test-connections.cjs` for settings persistence, source validation, authentication, failed-save preservation and cache refresh checks.
